安装 Leno 与第一个项目

目标：从零到"我的程序能双击运行"，每一步都实测过（Windows 环境，命令可直接抄）。 只想先看看语法长什么样，读 Leno零基础入门.md 就够了，那篇不需要装任何东西。

1. 你需要的东西

只有一个文件：leno.exe（编译器 + 运行器 + 打包器三合一）。

它从哪来？两种：

来源 说明
别人给你 仓库的 build\leno.exe，直接拿走就能用，无需安装、无依赖
自己编译 仓库根目录跑 build.bat（需要 gcc；本文实测用的是 MinGW gcc 15.2）

另外还需要 leno_vm.exe（build_vm.bat 生成）——只有"把 .lenb 交付给别人跑"和 -p 打包时才需要。 纯粹的 leno xxx.leno 直跑不需要它。

macOS / Linux 用 build.sh（同一份源码列表，产物同名）。

2. 让它能在任何目录被调用

最省事的做法：把 build\leno.exe 所在的目录加进 PATH。

当前窗口临时生效（关掉就没了，适合试）：

set PATH=D:\CLeno\Leno\build;%PATH%
leno --version

永久生效（新开窗口才有）：

setx PATH "%PATH%;D:\CLeno\Leno\build"

不想改环境变量也行，那就每次写全路径：

D:\CLeno\Leno\build\leno.exe hello.leno

下文一律写 leno，请自行替换成实际路径。

验证装好了

leno --version

实测输出（示例）：

LenoLang Compiler 0.3.0

3. 第一个程序

新建 hello.leno：

main() {
    print("你好，Leno！")
}

跑：

leno hello.leno

你好，Leno！

⚠ 两个新手常踩的坑： 1. 选项必须写在文件名之前：leno -p hello.leno 对，leno hello.leno -p 会把 -p 当脚本参数。 2. 路径带空格要加引号：leno "D:\我的 项目\hello.leno"。

4. 三种"交付"方式，按需要选

4.1 直跑（开发时用）

leno hello.leno

改一次跑一次，最简单。

4.2 编译成 .lenb 字节码（不想给对方源码）

leno -c hello.leno          :: 产出 hello.lenb
leno_vm.exe hello.lenb      :: 用 VM 跑（需要 leno_vm.exe 在同目录或 PATH 里）

⚠ .lenb 是绑定版本的：换了 leno_vm.exe 版本可能读不了，交付时要连 VM 一起给。

4.3 打包成独立 exe（给最终用户，双击就能跑）

leno -p -o=dist hello.leno

实测输出：

[pack] 输出目录: dist
[pack] 无需复制原生库（依赖里没有原生库声明）
打包成功: hello.leno -> dist\hello.exe (1048.0 KB)

dist\hello.exe 双击或命令行都行，对方不需要装 Leno：

dist\hello.exe

想要"就一个文件、不要旁边一堆 dll"，加 --onefile（原生库与资源内嵌，首次运行解包到用户缓存）：

leno -p --onefile -o=dist hello.leno

GUI 程序不想弹黑框：加 --no-console；反过来要强制带控制台：--console。

5. 正经项目：用 --init 起骨架

不要一上来就手搓目录。空目录里：

leno --init

实测输出：

[leno init] 包 'my-package' 创建成功！
目录: .
文件: leno.toml, lib/my-package.leno, src/main.leno
AGENTS.md（默认写法约定）, test/smoke.leno（冒烟测试）
模块别名: my_package（包名 my-package 含非法字符时用下划线替换）
运行: leno src/main.leno

生成的结构：

my-package/
├── leno.toml            包信息 + 依赖 + 模块根目录
├── AGENTS.md            这个项目的写法约定（给 AI 和自己看的）
├── lib/
│   └── my-package.leno  可复用模块（export 出去给 src 里的代码用）
├── src/
│   └── main.leno        入口，自带 5 种惯用写法示例
└── test/
    └── smoke.leno       冒烟测试

直接跑（无需任何配置）：

leno src/main.leno

实测输出开头：

Hello from my-package!

已完成 1 项：
· 写个可运行的样例

leno.toml 长什么样（实测生成内容）

[package]
name = "my-package"
version = "0.1.0"
description = "A Leno package"
authors = ""
license = "Apache-2.0"
leno_version = ">=0.1.0"

[dependencies]

[dev-dependencies]

[modules]
root = "lib"

常用的改动只有两处：name / version，以及往 [dependencies] 里加依赖（详见 包管理与安装使用指南.md）。

6. 保存前自检：--check

--check 会完整编译（含被 import 的模块）但不产出文件，只报错：

leno --check src/main.leno

全过时：

编译检查通过: src\main.leno（未产出 .lenb）

有错时退出码非 0，可直接接进脚本/CI：

leno --check src\main.leno || echo 有问题

建议：每次改完先 --check，再 leno 跑。--check 会连 import 的模块一起查， 能抓到"模块改坏了但当前文件还没跑到那行"这种问题。

7. 编辑器与 LSP（可选）

仓库自带语言服务器 leno_lsp/（纯 C，无第三方依赖）：

cd leno_lsp
build_lsp.bat            :: 产出 leno_lsp\build\leno_lsp.exe

它走标准 stdio LSP（stdin 读请求、stdout 写响应），所以任何支持"自定义 stdio 命令"的编辑器都能接。 leno_lsp\build\leno_lsp.exe 启动后不会打印任何东西——这是正常的，它在等 LSP 报文。

怎么确认它工作正常（不依赖任何编辑器，直接发报文）：

powershell -NoProfile -ExecutionPolicy Bypass -File leno_lsp\test_lsp_surface.ps1

实测结尾：

ALL LSP SURFACE CHECKS PASSED

这个脚本一次会话跑 21 条判据：关键字补全、hover（defer / thread_local / 带载荷 enum）、 代码大纲（main() / thread_local var / union）、Msg. 成员补全、内置函数补全、语法零错误诊断。 改完 LSP 先跑它，比在编辑器里手动点开补全快得多。

8. 环境坑速查（都是实测踩过的）

现象 原因 / 怎么办
控制台中文变乱码 控制台代码页不是 UTF-8：先 chcp 65001，或在 Windows Terminal 里跑
'leno' 不是内部或外部命令 PATH 没配，或 setx 之后没开新窗口
leno hello.leno -p 没打包 选项必须写在文件名之前
打包出来双击闪退 用 --console 打包一次看报错（默认已经是控制台版；GUI 程序才用 --no-console）
改了模块但行为没变 模块缓存：删掉项目里的 .lenocache 或改一次 exe（缓存绑定 exe 指纹）
文件删不掉 程序里打开了句柄没关：files.open 之后 defer f.close()（Windows 上句柄没关就删不掉）
