Android「正经 App」路线：复用清单 + 缺口清单

写于 2026-11-19。前提是 18 个探针在模拟器上 163/163 全绿， 且一个 WebView 形态的小应用（android/app/assets/app_web.leno）已经端到端跑通。 本文只回答两件事：手上现成的东西哪些能直接用、要补哪些才算正经 app。

0. 一句话结论

构建链、宿主骨架、22 个 Leno 模块、5 个原生库的双 ABI 产物、18 个探针， 这些都不用重写；真正缺的只有两块 —— 界面层 和 系统能力桥（通知/权限/分享/生命周期）。 界面层现在有两条已验证的路（文本、WebView），第三条（原生控件）的基础（dlsym 自身符号）也已实测可用。

1. 零改动直接复用

组件 位置 规模 作用
打包脚本 android/build_android.sh 219 行 aapt2 link → javac → d8 → apkadd → zipalign → apksigner，全程无 Gradle
APK 注入器 android/tools/apkadd.leno 215 行 往 base.apk 里补 dex / .so（已有条目按原始字节搬运，不重压）
JNI 胶水 android/app/jni/leno_jni.c 286 行 JNI_OnLoad 存 JavaVM、stdout→管道→Java、setDataDir、buildInfo
宿主 Activity android/app/java/.../MainActivity.java 212 行 asset 解包、后台线程跑 VM、双形态 UI（log / web）
探针套件 android/app/assets/c*.leno + s*.leno + run_probes.sh 18 个 / 163 断言 每次改 .so 或模块后一键回归
能力文档 docs/Android能力实测_2026-11-18.md — 能力分档 + 11 条踩坑记录

3. 缺口清单（按"上来就会踩"排序）

# 缺口 现状证据 影响
1 界面层 已落地三条：文本（TextView）、ui=web（WebView）、SDL3 控件层（SdlActivity，见 5.4） 已不再是缺口
2 assets 只能按名拷一个 ✅ 已修（2026-11-19）：SdlActivity 收 --es assetsdir <目录> 递归展开整棵资源树；同时修掉 aapt2 在 Windows 上把子目录条目名写成反斜杠的问题（新工具 android/tools/assetpaths.leno） 多页面/图片/字体资源可用
3 生命周期不通知 VM onPause/onStop/onDestroy 都没有；VM 线程阻塞在脚本里 切后台不停算、来电不暂停、退出不落盘
4 没有 Java→Leno 的函数调用 leno_vm_runtime.h 只导出 run_lenb / run_chunk_only 事件只能靠"脚本轮询"，不能"回调进函数"
5 权限只有 INTERNET AndroidManifest.xml 仅一条 <uses-permission> 相机/相册/通知/定位全不可用
6 存储只有 filesDir() setDataDir(getFilesDir()) 之后 _tmpdir() 指向应用私有目录 导出文件到"下载"、读相册、共享给别的 app 都做不到
7 无后台 / 通知 / 定时 无 Service / NotificationChannel / AlarmManager 只能是前台 app
8 debug 签名 + 无图标 debug.keystore 自动生成；manifest 无 android:icon 不能上架，装到别人机器上没图标
9 崩溃无兜底 Java 侧 catch (Throwable) 只兜 Java 异常；native SIGSEGV 直接挂进程 线上排障只能看 tombstone
10 单 APK 双 ABI 17MB ABIS="arm64-v8a x86_64" 一起打 体积翻倍，需 ABI split / AAB
11 无 i18n 资源 无 res/values-*，文案写死在脚本 可以在 Leno 里用 Dict 按 locale 取，代价低

3.4 的临时解法已在用：ffi.pump_callbacks() 可以在脚本里主动"收事件"， 配合 ffi.callback 把 C 侧回调排进队列（本次探针已验证该机制在 Android 上可用）。

4. 界面层三条路线

路线 复用 需新写 手感 风险 适合
A 文本 现有宿主 0 改动 0 无 无 命令行工具、探针、内部工具
B WebView + 本地 HTTP LenoHTTP(2346) + sockets + 现有宿主（已加 ui=web） HTML/CSS/JS（纯前端） 接近混合应用 首帧偶发绘制残留（模拟器软渲染，见 5.3） 表单/列表/看板类业务 app
C JNI 原生控件桥 现有 leno_jni.c + ffi.load("libleno.so").dlsym(...)（已验证） C 胶水 ~200 行 + 每个控件两侧各写一次 原生 控件多则胶水膨胀 少量系统级控件（Toast/通知/权限弹窗）
D SDL3 控件层 32920 行控件现成（跨桌面/安卓同一套 UI） ✅ 已落地（见 5.4）：新增 SdlActivity 继承官方 org.libsdl.app.SDLActivity，VM 跑在 SDL 主线程 原生自绘，桌面安卓同一套界面 需要打包 SDL 官方 Java 类（6130 行，已在模块里）；坐标按像素、无 DPI 缩放 游戏化/自绘/要桌面安卓同一套界面

推荐组合：B 起步（业务界面最快），C 补 3~5 个系统能力（Toast、通知、权限、分享）， D 用在"要桌面/安卓同一套自绘界面"或游戏化的场景 —— D 现在已经能跑（5.4 有实测）。

5.2 WebView 形态端到端

  • 页面由 app_web.leno 生成（170 行）：SQLite 表 + 三个路由（/、/api/list、/api/add）
  • 界面：卡片式看板，点「保存」→ fetch POST → SQLite 落盘 → location.reload()
  • 设备侧另用 adb forward tcp:18081 tcp:18080 + curl 直接验证接口： POST /api/add 后 GET /api/list 返回 count:2，重启 app 后数据仍在（真落盘）
  • 同一份脚本在桌面直接可跑：build\leno.exe android\app\assets\app_web.leno，浏览器开 127.0.0.1:18080

5.3 一个已知小问题

模拟器（swiftshader 软渲染）首次进入 WebView 时，第一帧偶发"内容错位"—— 卡片被画进相邻卡片的位置，等二次重绘（重进或数据刷新）就正常。 真机 GPU 渲染未复现；若在意，可在 onPageFinished 里下发一次 invalidate()。

5.4 SDL3 开窗（路线 D 已落地）

根因：libSDL3.so 的 JavaVM 只在它自己的 JNI_OnLoad 里缓存，而 ffi.load 走 dlopen ——dlopen 不触发 JNI_OnLoad ⇒ SDL 内部 mJavaVM == NULL ⇒ SDL_Init(VIDEO) 报 "Failed, there is no JavaVM"（src/core/android/SDL_android.c:491）。 手动补调它的 JNI_OnLoad 会让进程直接 abort（FindClass("org/libsdl/app/SDLActivity") 失败 ⇒ pending exception ⇒ ART AssertNoPendingException）。

做法（4 个文件）：

文件 改动
android/app/java/com/leno/app/SdlActivity.java 新增，继承 org.libsdl.app.SDLActivity；getLibraries()={SDL3,SDL3_image,SDL3_ttf,leno}、getMainFunction()="leno_sdl_main"、getArguments()={.lenb 路径}
android/build_android.sh javac 的源列表加上 SDL 官方 Java 目录（6130 行，模块里自带，不额外下载）
android/app/jni/leno_jni.c 新增 leno_sdl_main()：在 SDL 主线程上跑 lenolang_run_lenb；stdout 接管支持 NULL sink（只镜像 logcat）
android/app/AndroidManifest.xml 加 .SdlActivity（configChanges 按 SDL 官方清单那一串）

顺带修掉的三个模块缺陷（都在 LenoSDL3/lib/）：

  1. sdl_font.leno 的 createFontAuto 没有 android 分支 ⇒ 落到 linux_font_find() 递归扫描 ⇒ 打印"没扫到可用中文字体"、拿不存在的 DejaVu 路径去开 ⇒ 控件都画出来了但一个字没有

5.5 实战：LenoMusic（16.6k 行真 app）原样打成安卓包

2026-11-19。挑它的原因：它比 Aria（26.9k 行）轻，但该有的都有 —— LenoSDL3 控件层、多站搜索（酷我/网易云/QQ/酷狗）、线程 + channel、LenoWeb/LenoCurl、 本地文件落盘。源码一行没改就编出了 .lenb 并在模拟器里跑通。

产物与跑法

# 1) 桌面编译器出字节码（4.4s / 1.2MB）
cd /d/CLeno/LenoMusic && /d/CLeno/Leno/build/leno.exe -c musicdl_gui.leno
# 2) 放进 assets（.lenb + images/ 整棵）
cp musicdl_gui.lenb /d/CLeno/Leno/android/app/assets/lmusic/

# 4) 启动（横屏；界面是按桌面 1060×680 设计的）

adb shell am start -n com.leno.app/.SdlActivity --es assetsdir lmusic --es asset musicdl_gui.lenb

这一趟逼出来的 4 个真缺陷（都已修）

  1. aapt2 在 Windows 上把嵌套 assets 的条目名写成反斜杠 assets/lmusic\images\about.png（unzip -l 可见）⇒ AssetManager.list/open 按 / 查不到。 平铺 assets 没分隔符所以一直没暴露。修法：新增 android/tools/assetpaths.leno， 在 aapt2 之后把条目名里的 \ 原地换成 /（等长替换，偏移/CRC/压缩数据全不动）， build_android.sh 新增 2.5/6 步调用。
  2. dirs.script_dir() 在嵌入宿主下返回 null 它只看 g_argv，而 Android 的 argv[0] 是 SDL 塞的 "app_process" ⇒ realpath 失败。 同一个进程里 _script()（看注入）却有值 —— 同一语义两套口径。 修法：sys.c 新增 leno_script_path() getter，dirs.c 优先取注入值。 现场症状是 dirs.join(script_dir(), "downloads") 抛"第 1 个参数是 null"。
  3. 一个窗口里有两个以上 Edit 时，文本输入被自己的兄弟控件关掉 Edit.blur() 无条件调 core.stopTextInput(hwnd)，而它是窗口级的； MOUSE_DOWN 又是广播给所有控件的 ⇒ 点 A 框时 B 框算出"不在我身上"→ 自己 blur() → 把整个窗口的文本输入关掉 ⇒ 软键盘闪一下就消失、SDL_EVENT_TEXT_INPUT 一条不来。 修法：sdl_edit.blur() 只有原本 focused 才关。单输入框界面（app_text）不会触发， 所以此前一直没暴露。手工回归探针：android/app/assets/m_nestedit.leno（m* 不进自动套件）。
  4. 二级窗口在 Android 上建不出来（未修，属架构级） 下载窗口走 SDL3.createModelessDialog ⇒ 第二个 SDL 窗口。Android 上 SDL3 只有单窗口， 创建失败后 dlg.ok == false ⇒ 框架"只在 ok 时才碰 SDL"⇒ 点「下载勾选」毫无反应， 也不报错（dumpsys window 只有 1 个 SdlActivity 窗口可佐证）。 要让它可用，得把这类窗口改成同窗口内的浮层（框架级改动，不是应用侧能绕的）。

结论："能打包"已经不是问题，"有二级窗口的界面"才是。 单窗口 + 自绘浮层的应用（Aria、LenoMusic 主界面、看板/工具类）现在就能上； 靠多窗口做对话框的老界面，要么改成浮层，要么等框架补这一层。

5.6 一次误诊记录：跨模块 struct 跨线程是好的，错的是调用点

LenoMusic 上安卓后，双击榜单行"边下边播"表现为：播放条转成暂停图标、时间停在 0:00 / 0:00、 downloads/试听缓存/ 一个字节都没有，而主线程照常 96% CPU 跑渲染 —— 也就是"点了没反应"。

第一版判断是 VM 缺陷：channel_clone_struct 在子线程 re-clone 时，跨模块的 struct 定义 对不上，克隆出 null。这个判断是错的，反证在仓库里：

证据 结果
assert/test_thread_crossmod_struct.leno（struct 定义在另一个模块，实例经 Array[fx.Item] 跨线程） 通过：字段完整、深拷贝生效、空数组也正常
assert/probe_thread_shape_mismatch.leno（同一 worker，改传 Array[Array[string]]） 报 字段访问需要结构体对象，桌面即可复现（与安卓无关）
内联 struct 探针 m_xstruct.leno（定义与用法同一文件） 正常

真因是调用点传错了形状：dl_flow.start_stream 把 wire 行（Array[string]）直接递给 worker：

// 原来：one 是行（Array[string]），worker 形参却是 Array[srow.SongRow]
streamThread = threads.start(dlWorker, [one], …)
// 现在：转换点仍然只有一个（songrow.from_row）
Array[srow.SongRow] oneJob = [srow.from_row(one)]
streamThread = threads.start(dlWorker, oneJob, …)

于是子线程拿到的元素是数组，第一句 job.name 就抛异常。而 threads.start 是 native 调用， 参数类型不做检查（threads_check_entry 只查 arity）⇒ 编译器也不会拦。

同时补了两处：eng.songlabel(w.jobs[k]) 把 SongRow 当行用（同样会炸）、dlWorker 的形参类型 从 Array[Array[string]] 订正为 Array[srow.SongRow]；并在应用侧加了 stream_watchdog() —— 线程 state() == "error" 时把 error() 打到状态栏。静默死掉才是这条 bug 难查的真正原因， 报错本身一直存在（Thread.state/error，TH11），只是没人去问。

修后安卓实测：双击榜单行 → 41~54 MB flac 整首下完 + .lrc 落地、 AAudioStream_requestStart(s#1) returned 0、播放条 0:09 → 0:42 / 4:03 连续推进。

build\leno.exe android\app\assets\app_web.leno

# 安卓：文本形态

# 安卓：WebView 形态
adb shell am start -n com.leno.app/.MainActivity --es asset app_web.lenb --es ui web

7. 下一步的最小闭环（若要正式起一个 app 项目）

  1. ✅ 二级窗口 → 同窗口浮层（优先，2026-11-19 新增）：createModelessDialog / createDialogWindow 在 Android 上建不出窗口 ⇒ 任何"点按钮弹个框"的界面都会静默失效 （LenoMusic 的下载窗口就是）。框架级改动：在 sdl_window 里加一层"浮层窗口"， 由主窗口的事件循环与渲染器统一处理。

  3. ✅ asset 全量解包（--es assetsdir，含 aapt2 反斜杠修正）—— 缺口 2 已关闭
  4. 加 onPause/onResume/onDestroy → 写一个 state 文件，脚本轮询——解决缺口 3
