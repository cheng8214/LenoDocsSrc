错误与空值契约（P2）

面向"这段代码该返回什么"的决策文档。依据：docs/Leno真实项目可用性评估_2026-11-08.md §2.8 / §4.5.1 的统计（8 种错误表达、4 类空值哨兵），以及 2026-11-09 的落地 （import "Result" 模块 + SQLite NULL 语义）。

一句话：失败用 Result[T]，缺值用 Option[T]，进程内判空继续用 T?；SQL 的 NULL 永远是 null。

1. 修前是什么样（问题）

错误表达 出处 调用方要做什么
Dict{ok, err} LenoSqlite execWithErr 取 _str(d["err"]) 判空
bool LenoFS / LenoCsv 若干 拿不到原因
int -1 / rc LenoSqlite exec/step、LenoDir 要背 SQLite 常量
typed Result struct LenoWeb web_generic（已删） 只在 Web 里有，别处没有
error 字段 LenoHTTP Response 与 ok() 配合，各自实现
throw Aria / LenoWorkBuddy catch e 只能打日志
Result[T]（自制） 各项目 字段名 / 成功判据各不同
Response.ok() LenoHTTP 只适用 HTTP

空值同理：null、""、0、[] 四种哨兵混用，最典型的是 SQLite 把 NULL 压成 "" / 0（column_text(NULL) ⇒ ""），于是"这列没有值"和"这列的值就是空串"永久分不清。

2. 修后：一套形态

import "Result" as res
use res.(Result, Option)

2.1 Result[T]

字段 含义
bool ok 唯一成功判据（不要用 code == 0）
int code ErrCode 之一：INVALID_ARG / NOT_FOUND / PARSE / IO / NET / DB / AUTH / CONFLICT / UNSUPPORTED / INTERNAL
string msg 给人看的一句话（成功时为空）
T val 成功时的值（失败时无意义，不要读）

方法：isOk / isErr / get / unwrap / orElse / errName / errText。 函数：ok / err / errText / mapResult / flatMap。

跨模块时 .val 也是精确类型（2026-11-11 修）：Result[Pay] r = m.make() 之后 r.val.token.len() 直接可用，不需要 as Pay 或中间变量标注。 修前跨模块读泛型字段会把类型退化成 any（Box[Pay].v 同样中招）—— 同模块内测不出来，只在"库 + 应用"分仓时暴露；回归见 assert/test_generic_field_cross_module.leno。

为什么是 struct 而不是载荷 enum（2026-11-10 两次实测复核）： · enum 现在能带载荷（enum Msg { progress(int done, int total) }）； · 泛型载荷 enum 现在完整可用（2026-11-10，步 1~3）：声明 / 构造（类型实参从上下文 推断）/ 匹配都通； · 但 enum 不能挂方法（extend 只接受 struct）—— 而 Result 的价值全在方法上 （isOk / orElse / unwrap / errText）⇒ 换 enum 等于让所有调用点改成 switch， 是破坏性变更，还丢掉 orElse(默认值) 的显式性。 ⇒ 结论：Result[T] / Option[T] 保持 struct —— 不是"语言不支持泛型 enum"（已经支持了）， 而是"enum 是值、不能有方法"这条更有意的限制。 反过来：不需要泛型的结果形态应当写成载荷 enum（可读性更好，还能吃到 switch 穷尽性检查），例如 enum Fetch { ok(string body), fail(int code, string msg) }。

2.2 Option[T]

some / val + isSome / isNone / get / unwrap / orElse；函数 some / none / mapOption。

与 T? 的分工：函数内部的临时判空继续用 T?（零成本）；跨模块边界要表达 "可能没有值"就用 Option[T] —— 它能放进 Result、数组、Dict，且不会与 null 混成一体。

2.3 严格解析

res.parseInt / res.parseFloat 取代 _int / _int_or / as int 三套不一致语义：

res.parseInt("42").val        // 42
res.parseInt(" 42").isErr()   // true —— 严格，不替你去空格
res.parseInt("12a").errText() // "PARSE: 不是整数（含非数字字符）：12a"

3. 迁移对照（旧写法 → 新写法）

旧写法 新写法
Dict d = f(); if _str(d["err"]) != "" { ... } Result[T] r = f(); if r.isErr() { ... r.code ... }
bool ok = f(); if not ok { ... } Result[T]，code 说明原因
int rc = ...; if rc != SQLITE_OK 保留（SQLite 原生码），但新 API 不许再返回裸 rc
if x == "" { 缺值 } Option[T] 或 x is null 判
int n = _int_or(s, 0) res.parseInt(s).orElse(0)（默认值写在调用点）
throw "INVALID_FORMAT" res.err[T](res.ErrCode.PARSE, "...")；throw 只留给"程序 bug"
SQLite column_text(NULL) ⇒ "" column_is_null(i) / column_value(i) ⇒ null

4. SQLite NULL 语义（2026-11-09 起）

stmt.forEach(func(Statement s): bool {
    if s.column_is_null(2) { /* 这一格就是 NULL */ }
    var v = s.column_value(2)      // null / int / float / string / Ptr(BLOB)
    return true
})

queryAll(path, sql) 同步改了：INTEGER ⇒ int（不再是 "123"）、FLOAT ⇒ float、 NULL ⇒ null（不再是 ""）、BLOB ⇒ 字节数。仓库内零调用方，改语义不打断任何项目。

column_text / column_int / column_double 保留：给"已确认非空"的热路径省一次分支， 但新代码应优先 column_value —— 否则 NULL 又会悄悄变成 0。

5. 哪些模块已经收敛了（2026-11-09）

判断标准：这条路径真的会失败吗？会 → Result；不会 → 直接返回数据（别造"永远 ok 的 Result"）。

模块 旧口径 新口径 调用点影响
LenoFS Dict{ok,files,dirs,err} Result[FsCount]（NOT_FOUND/INVALID_ARG/CONFLICT/IO） 只有自己测试
LenoCSV parseTable/load ⇒ Dict{ok,header,rows,err}；save ⇒ bool parseTable ⇒ CsvTable（不会失败）；load ⇒ Result[CsvTable]；save ⇒ Result[int]（字节数） 只有自己测试 + 开发工具
LenoSqlite execWithErr ⇒ Dict{rc,err}；prepare 只给 isOk()==false execResult ⇒ Result[int]（受影响行数）；prepareResult ⇒ Result[Statement]；NULL 用 column_value/column_is_null 只有自己测试
LenoCompress gunzip/inflateZlib/inflateRaw ⇒ GzipResult{ok,data,error,…} Result[Inflated]（Inflated{data,inBytes,outBytes}，失败 ErrCode.PARSE） LenoZip / LenoHTTP 测试 / LenoWeb（web_gzip、Web、WebHtml）已同步
LenoStats 空数组 ⇒ 0.0；money ⇒ Dict{ok,cents,err} mean/median/percentile/stdev*/minInt/maxInt ⇒ Option[T]；money ⇒ Result[int] 4 个项目 0 引用

应用侧自造 Result 的迁移（2026-11-10）

仓库 原来 现在
Aria AuthResult{ok,msg,token,uid,…}（9 字段混装） Result[AuthOk]（AuthOk 只装成功载荷；失败带 INVALID_ARG/AUTH/NET/PARSE）
LenoMusic parse_uint: [int, bool] / parse_word_span: [float, float, bool] Result[int] / Result[WordSpan{start,dur}]（失败 PARSE）

6. 还没做的（诚实清单）

  • 其余模块的老 API 没逐个改：LenoWeb 的若干 bool、LenoHTTP 的 Response.ok()、 LenoQR/LenoCompress 的 Dict。按上面的标准逐条迁移，不做一次性推平。
  • HTTP Response.ok() 与 Result 并存：HTTP 那条是协议层结果（含状态码/头）， 不是"操作失败"，短期不动。
  • 四个应用里自造的 Result / parse_uint / Num 仍在（跨仓改动，等各仓自己轮到）。
  • 错误码的穷尽检查只覆盖 enum 主题（switch code，code 是 enum 类型时）： 漏 case 且无 default ⇒ WARN_SWITCH_NOT_EXHAUSTIVE 并列缺失成员（2026-11-10，P4）。 int 错误码（如 Result.code）仍然不报 —— 它不是 enum，成员集合编译期不可知。
  • Result[T] 目前不能带"多值成功"（要两个值就包一层 struct）。
  • enum 不能挂方法（extend 只接受 struct）⇒ Result[T] / Option[T] 只能是 struct （泛型载荷 enum 本身 2026-11-10 起已完整支持，理由见 §2.1 的引用块）。
