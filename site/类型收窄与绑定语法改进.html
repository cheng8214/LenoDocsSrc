类型守卫收窄与 => 绑定语法改进文档

本文档基于实际编译运行验证，记录 is 类型收窄与 => 绑定语法在泛型容器取值场景下的类型语义、已知边界行为与最佳实践。 所有结论均由 examples/type类型/ 下的测试文件实测验证，非推测。

一、核心语义：泛型收窄决定取出元素的类型

用户提出并验证过的关键论断：

收窄成裸 Array / Dict 取出元素是 any —— 这是正常行为。 只有收窄成带泛型参数的 Array[int]、Dict[string, int] 这种，取出来的元素才是带类型的。

这个论断正确，且是理解整个收窄体系的基础：

收窄目标类型 取出元素/值的类型 是否能直接使用
Array（裸） any ❌ 需再收窄或强转
Array[int] int ✅ 可直接算术
Dict（裸） any ❌ 需再收窄或强转
Dict[string, int] int ✅ 可直接算术 
// 裸 Array：arr[0] 是 any，需再收窄
if x is Array => arr {
    var first = arr[0]      // first 是 any
    if first is int {
        return first        // 收窄传导到变量 first
    }
}

// Array[int]：arr[0] 直接是 int，可算术
if x is Array[int] => arr {
    return arr[0] + 1       // ✅ 无需再收窄
}

// 裸 Dict：d["a"] 是 any，需再收窄
if x is Dict => d {
    var v = d["a"]          // v 是 any
    if v is int {
        return v
    }
}

// Dict[string,int]：d["a"] 直接是 int，可算术
if x is Dict[string, int] => d {
    return d["a"] + 1       // ✅ 无需再收窄
}

泛型收窄是运行时元素类型检查

验证发现：x is Array[int] 的收窄是运行时检查数组的每个元素是否为 int。

var int_arr = [10, 20, 30]        // 全是 int
var mixed_arr = [10, "hi", 3.14]  // 混有非 int

if int_arr is Array[int] { }      // ✅ true
if mixed_arr is Array[int] { }    // ❌ false（即便第一个元素是 int）

因此： - Array[int] 语义 = "全是 int 的数组"，混入其他类型即为 false。 - 想匹配"首个元素是 int"而不是"全部是 int"，应使用元素级收窄： leno if x is Array => arr { if arr[0] is int => n { // 只关心第一个元素 // ... } }

二、=> 绑定语法基础回顾

if expr is Type => var { ... } 一次性解决三个问题：临时变量泄漏、重复求值、冗余 as 转换。

if expr is Type => var {
    // var 在块内就是 Type，不需要 as
    // expr 只求值一次
    // var 只在 {} 内存在
}

核心特性（已实测）： - ✅ expr 只求值一次（有副作用也安全） - ✅ var 类型已收窄为 Type - ✅ var 作用域仅在 then 块内（else 与块外访问报"未定义变量"） - ✅ 支持基本类型、struct、enum、face、泛型、null

三、已验证的边界行为与限制

以下行为均经 examples/type类型/测试嵌套解包方案.leno 实测确认。

✅ 限制 1：and 守卫链 + => 绑定已修复

已修复：if x is Array => a and a[0] is float {} 现在可以正常使用。 修改了 parser，将 => 绑定检查从 and/or 循环之后移到之前， 并在 fallback 路径中保留 guard_bind_var 不清除。

// ✅ 现在支持：=> 绑定 + and 链
if x is Array => a and a[0] is float {
    // a 已绑定为 Array，a[0] 已收窄为 float
    return a[0] + 0.1
}
// ✅ 也支持 int、string 等
if x is Array => a and a[0] is int {
    return a[0] + 1
}
if x is Array => a and a[0] is string {
    return a[0] + "!"
}

✅ 限制 2：连续索引收窄已修复

已修复：a[0]["a"] is string 的编译期收窄已实现。 修复方案：在守卫提取逻辑中识别嵌套 AST_INDEX（即 expr->u.index.obj->kind == AST_INDEX）， 递归提取内层变量名和两层索引键，拼装为 "inner][outer" 格式存入 index_key。 守卫符号创建时用 "%s[%s]" 格式生成 "a[0][key]" 符号名。 类型推断时同样递归构造完整路径 "a[0][key]" 查找守卫符号。

// ✅ 现在支持：a[0]["a"] 连续索引收窄
if a is Array and a[0] is Dict and a[0]["a"] is string {
    return a[0]["a"]   // ✅ a[0]["a"] 已收窄为 string
}
// ✅ 也支持 int、float 等
if a is Array and a[0] is Dict and a[0]["val"] is int {
    return a[0]["val"] + 1   // ✅ 可算术
}
// ✅ 支持多连续索引 + and 链
if a is Array and a[0] is Dict and a[0]["a"] is int and a[0]["b"] is int {
    return a[0]["a"] + a[0]["b"]   // ✅ 两个都已收窄
}
// ✅ 支持连续索引 + => 绑定
if a is Array => arr and arr[0] is Dict and arr[0]["name"] is string {
    return arr[0]["name"]   // ✅ 已收窄
}
// ✅ 支持连续索引收窄传导到局部变量
if a is Array and a[0] is Dict and a[0]["val"] is int {
    var n = a[0]["val"]   // ✅ n 继承 int 类型
    return n + 100        // ✅ 可算术
}

✅ 限制 3：收窄信息传导到局部变量已修复

已修复：索引守卫修复后，var d = arr[0] 时 d 能继承 arr[0] 的守卫类型（如 Dict）， 因为类型推断在访问 arr[0] 时会查到守卫符号 "arr[0]" 并返回收窄后的类型。

// ✅ 现在支持：var d = arr[0] 后，d 继承守卫类型
if a is Array and a[0] is Dict {
    var d = a[0]   // ✅ d 的类型推断为 Dict（继承索引守卫）
    d["name"]      // ✅ 可访问（裸 Dict 返回 any，但可再收窄）
}
// ✅ 也支持 int 类型传导
if a is Array and a[0] is int {
    var n = a[0]   // n 继承 int 类型
    return n + 100  // ✅ 可算术
}
// ✅ 还支持嵌套：d["items"] is Array → var arr = d["items"]
if a is Dict and a["items"] is Array {
    var arr = a["items"]  // arr 继承 Array 类型
    if arr[0] is int {
        return arr[0] + 1  // ✅ arr[0] 有索引守卫
    }
}

✅ 限制 4：数组索引收窄已修复（原编译器 bug）

已修复：arr[0] is int 和 d["name"] is int 的编译期收窄现已实现。 修复方案：在语义分析阶段从 AST_TYPE_CHECK 的 expr 中识别 AST_INDEX 节点， 提取变量名和索引键（数字、字符串、变量），在 then 块作用域中创建 "arr[0]" 格式的守卫符号。

// ✅ 现在支持：arr[0] is int 的编译期收窄已实现
if x is Array => arr {
    if arr[0] is int {
        return arr[0] + 1  // ✅ arr[0] 已收窄为 int，可算术
    }
}
// ✅ 也支持：d["name"] is string 的编译期收窄
if x is Dict => d {
    if d["name"] is string {
        return d["name"] + "!"  // ✅ d["name"] 已收窄为 string
    }
}
// ✅ 还支持：大索引、多个索引、and 短路
if x is Array => arr {
    if arr[10] is int {           // 大索引
        return arr[10] + 100
    }
    if arr[0] is int and arr[1] is int {  // and 短路多索引
        return arr[0] + arr[1]
    }
}

支持的索引类型： | 索引形式 | 示例 | 守卫符号 | |---------|------|---------| | 数字常量 | arr[0]、arr[10] | "arr[0]"、"arr[10]" | | 字符串常量 | d["name"] | "d[name]" | | 变量索引 | arr[i] | "arr[i]" |

四、最佳实践

场景 1：逐步解包嵌套容器（数组→Dict→字段）

唯一类型安全且能编译的写法是嵌套 => 绑定：

func extract(any a): string
{
    if a is Array => b
    {
        if b[0] is Dict => c
        {
            if c["a"] is string => d
            {
                return d
            }
        }
    }
    return "NOT_FOUND"
}

场景 2：嵌套太深时，拆小函数

func extract_first_a(Array arr): string
{
    if arr[0] is Dict => c
    {
        if c["a"] is string => d
        {
            return d
        }
    }
    return "NOT_FOUND"
}

func test(any a): string
{
    if a is Array => arr
    {
        return extract_first_a(arr)  // 类型已收窄为 Array
    }
    return "NOT_FOUND"
}

场景 3：单层容器 + 元素级收窄

// 关注"首个元素是 int"，而不是"全部是 int"
if x is Array => arr
{
    if arr[0] is int => n
    {
        return n + 1   // n 是 int
    }
}

场景 4：能提前确定元素类型时，直接用泛型收窄

// 数据源保证全是 int，直接用 Array[int] 一步到位
if x is Array[int] => arr
{
    return arr[0] + 1   // 无需再收窄
}

场景 5：Dict[K, V] 的逐键值校验（v3.2.1）

// 解析外部 JSON 后常见形态：确认"键值都是 string"再当纯字符串表用
if raw is Dict[string, string] => db
{
    return db["host"]          // db 的静态/运行期都是 Dict[string, string]
}

语义（vm.c 的 type_spec_match + value_matches_kind，is 与 as 共用）：

表达式 结果 说明
{"a":"1"} is Dict[string,string] true 键值都对得上
{"a":1} is Dict[string,string] false 值为 int ⇒ 不匹配（修复前误判为 true）
{"a":null} is Dict[string,string] false null 值不算 string
{1:"a"} is Dict[string,string] false 键侧同样校验
{"a":1} is Dict[string,any] true any 表示该侧不校验（与旧行为一致）
{} is Dict[string,string] true 空字典恒匹配（无元素可违反）
{"a":1} as Dict[string,string] null as 不匹配给 null，不报错

⚠ 容器种类也参与校验：Array[T] 的逐元素检查此前把 TYPE_ARRAY 等落进 default（恒真）， 于是 [[1,2], 5] is Array[Array[int]] 曾返回 true；现在改为"顶层对象类型必须对上" ⇒ false。

场景 6：泛型实参递归校验 + 嵌套位置的名字校验（v3.2.2）

is/as 的泛型实参现在会完整带进运行期（递归类型规格），判定递归到底：

if raw is Dict[string, Array[int]] => m   // 每个值都必须是"全是 int 的数组"
if rows is Array[Array[int]] => r         // 每一层都要对
if items is Array[Rect] => rs             // 每个元素必须真的是 Rect（不是"随便一个 struct"）
if arr is Array[Shape] => ss              // face 也按名字比（impl 关系在运行期检查）
表达式 结果
[[[1]]] is Array[Array[Array[int]]] true
[[["x"]]] is Array[Array[Array[int]]] false
{"a":[1,2]} is Dict[string,Array[int]] true
{"a":[1,"x"]} is Dict[string,Array[int]] false
[Point, Point] is Array[Point] true
[Point, 5] is Array[Point] false
[Rect] is Array[Shape] true（Rect impl Shape）
[Rect] is Array[Point] false
{"p":Point} is Dict[string,Point] true
[0,1,2] is Array[Color]（enum） true —— 枚举成员运行期就是 int，语言本身不区分是哪个 enum

发射端只在"泛型实参带约束"时才用规格版指令（codegen_expr.c 的 type_needs_spec）： 裸 Array / Dict / Ptr 与带名字的 struct·face·enum 顶层仍走紧凑指令 ⇒ 热路径（case is Rect 之类）与旧版逐字节一致，零额外开销。

两条边界（有意为之，代码里有注释）：

  • 嵌套深度上限 32 层（TYPE_SPEC_MAX_DEPTH）：自引用容器（a.add(a)）会让递归判定无限下行 ⇒ 到顶即 fail-closed（判为不匹配，而不是崩或猜）。40 层嵌套 ⇒ is Array[Array[int]] 为 false， 但 is Array 仍为 true（顶层判定不受影响）。
  • Ptr[T] 只校验顶层是 FFI 指针（指针里没有"元素值"可递归）；as Ptr[T] 匹配后会把叶子 元素类型回填进 FFI 指针对象（与旧行为一致）。

⚠ 想深挖类型名为什么必须递归解析：parser 拿不到 face/enum 注册表 ⇒ Shape（face）、Color （enum）会先被记成 TYPE_STRUCT + 名字；v3.2.2 起嵌套实参的名字要带进运行期做校验，所以 semantic_type.c 的 resolve_type_names() 会把整棵类型树纠正过来（此前 6 处散装逻辑只修 最外层或只修数组元素，遇到 Array[Shape] 会拿 struct 名字去比 face 实例 ⇒ 误判）。

五·补、集合查询：过滤 / 映射 / 收窄的推荐写法（2026-10-22 实测）

背景：有人提议加 where x in arr if ... => x 语法。实测确认不需要 —— filter / map / reduce 早已具备且类型推断完整，唯一缺口（收窄）用 => 绑定 3 行就能写。

1. 过滤 / 映射：直接用 Array 方法

Array[int] evens = nums.filter(func(any x, any i) { return x % 2 == 0 })
Array[string] ss  = evens.map(func(any x, any i) { return _str(x) })   // 推成 Array[string] ✓

⚠ 闭包参数必须写两位（元素 + 索引），且做比较/算术时要标元素类型：

nums.filter(func(any x) { return x > 3 })         // ✗ 报「any 不能参与大小比较」
nums.filter(func(int x, any i) { return x > 3 })  // ✓ 显式标 int

2. 收窄过滤（filter 推不出 Array[T]）

filter 的返回规格是"保持元素类型"⇒ Array[any] 过滤完仍是 Array[any]，赋给 Array[int] 编译失败。

// ✅ 推荐：=> 绑定（类型守卫收窄）+ 手写收集 —— 3 行，类型完全安全
Array[int] ints = []
for mix to x {
    if x is int => v { ints.add(v) }
}

3. 扁平化：Array.flatten()（2026-10-22 新增）

Array[Array[int]] matrix = [[1, 2], [3], [4, 5]]
Array[int] flat = matrix.flatten()     // 类型精确是 Array[int] ⇒ flat[0] + 1 直接可写
  • 只压一层；非数组元素原样保留（不静默丢数据）；不修改源数组
  • 实现：native 层新增关系规格 NTYPE_ARG0_ELEM2（"第 0 个实参的二层元素"）
  • ⚠ 字面量 [[1,2],[3]] 的内层元素类型是"未指定"⇒ 想精确推断要先声明 Array[Array[int]]

4. 为什么不再加 where 语法

理由 说明
能力已覆盖 过滤/映射/链式/自推断都有；唯一缺口用 => 3 行解决
两套遍历语法 会同时存在 for arr to x 和 where x in arr，新手最易混淆
关键字是永久成本 parser/高亮/文档/报错文案都要为它让路，收益只有"3 行变 1 行"
