快速参考

type() - 获取类型

基本用法

返回值的类型字符串，支持精确的类型推断（包括泛型）。

// 基本类型
print(type(123))        // "int"
print(type(3.14))       // "float"
print(type("hello"))    // "string"
print(type(true))       // "bool"
print(type(null))       // "null"

// 数组类型（支持泛型推断）
print(type([1, 2, 3]))              // "Array[int]"
print(type([1.0, 2.0]))             // "Array[float]"
print(type([1, "hello"]))           // "Array[any]"
print(type([]))                     // "Array"

// 字典类型（支持泛型推断）
print(type({"a": 1, "b": 2}))       // "Dict[string, int]"
print(type({"x": 1.0, "y": 2.0}))   // "Dict[string, float]"
print(type({}))                     // "Dict"

// 函数类型
func add(int a, int b):int { return a + b }
print(type(add))        // "func"

// 大整数（bigint）⇒ 也报 "int"（**对外统一**，`x is int` 同样为真）
//   值本身是任意精度（超出 int48 自动升级），只是 type() 不区分 —— 想判 bigint 别靠 type()
print(type(99999999999999999999))   // "int"

⚠ 自引用容器（Dict[string,any] d; d["self"] = d、Array[any] a; a.add(a)）： type() 靠递归推断元素类型 ⇒ 成环时抛错 （type() 失败：嵌套超过 512 层（容器可能存在循环引用）），不再栈溢出崩溃（2026-11-16 修）。 同一族保护也在 .copy() 深拷贝、print() / _str()（后两者是地址栈环检测）。

嵌套类型推断

// 数组包含字典
var users = [{"name": "Alice"}, {"name": "Bob"}]
print(type(users))      // "Array[Dict[string, string]]"

// 字典包含数组
var data = {"scores": [85, 90, 95]}
print(type(data))       // "Dict[string, Array[int]]"

// 深层嵌套
var nested = {
    "level1": {
        "level2": {
            "value": 100
        }
    }
}
print(type(nested))     // "Dict[string, Dict[string, Dict[string, int]]]"

类型转换函数

_int(value) - 转换为整数

将值转换为 int 类型。

支持的转换:

原始类型 示例 结果
int _int(42) 42（直接返回）
float _int(3.14) 3（截断小数）
bool _int(true) 1
bool _int(false) 0
null _int(null) 0（⚠ 而 _int_or(null, d) 给的是 d，见下方边界表）
string _int("123") 123
大整数 _int("9999999999999999") 9999999999999999（int48 内仍是 int ✓；超出 int48 自动升级为 BigInt ✓）

范围（2026-09-25 起；浮点分支 2026-11-11 再次修正）：字符串分支走 strtoll + val_int_safe。浮点分支先排除 NaN / ±Inf（⇒ 运行时错误）；|d| 在 int64 内 ⇒ val_int_safe；超出 int64 ⇒ 用 %.0f 取该 double 的精确十进制展开，再交给 bigint （2026-11-11 前是"夹到 INT64_MAX" ⇒ _int(1e20) 静默变成 9223372036854775807，与 "_int 不改变数值"矛盾 ✗）。历史写法是 strtol + (int)：Windows 上 long 只有 32 位 ⇒ _int("9999999999999999") 被饱和成 2147483647；而在 long 是 64 位的平台上 (int) 又 变成截断（同一份代码跨平台两种错法 ✓）。超过 int64 的数字串（如 "18446744073709551616"） 交给 val_bigint_from_string 解析 ✓。

⚠ NaN / ±Inf 会抛错（_int(_float("nan")) ⇒「无法把 NaN / Infinity 转成整数」）， 不会静默给 0 / 饱和值。

// 基本转换
print(_int(3.14))       // 3
print(_int("100"))      // 100
print(_int(true))       // 1

// 从 any 转换
func getValue():any { return "42" }
var val = getValue()
var num = _int(val)     // 42

错误情况:

_int("12b3")            // ❌ 运行时错误：无法将字符串转换为整数："12b3"
_int("hello")           // ❌ 运行时错误：无法将字符串转换为整数："hello"
_int([1, 2, 3])         // ❌ 运行时错误：无法将该类型转换为整数

_float(value) - 转换为浮点数

将值转换为 float 类型。

支持的转换:

原始类型 示例 结果
int _float(42) 42.0
float _float(3.14) 3.14（直接返回）
bool _float(true) 1.0
bool _float(false) 0.0
string _float("3.14") 3.14
大整数 _float(超大整数值) 转换为 float（可能丢失精度，对外显示为 int） 
print(_float(42))       // 42.0
print(_float("3.14159")) // 3.14159
print(_float(true))     // 1.0

错误情况:

_float("abc")           // ❌ 运行时错误：无法将字符串转换为浮点数："abc"
_float("12.34.56")      // ❌ 运行时错误：无法将字符串转换为浮点数："12.34.56"

⚠ 报错带上了坏值（2026-10-07）：排查时"哪个值坏了"就是核心线索，而这条信息在抛出的 那一刻就在手上。与文件类报错（无法打开文件 '…' 一直带值）拉齐口径。

⚠ "nan" / "inf" / "-inf" 会被接受（走 C strtod 的口径）⇒ _float("nan") 得到 NaN、 _float("inf") 得到 inf。要"只认十进制数字"请用 LenoResult 的 parseFloat（严格解析，失败给 Result）；要转 int 时 NaN/Inf 会被 _int 拒绝（抛错）。

_int_or(value, default) / _float_or(value, default) - 容错转换（2026-10-07 新增）

转成功就返回结果，转不了（或类型不对）就返回 default，绝不抛异常。

情形 _int_or _float_or
合法数字串 _int_or("42", -1) → 42 _float_or("3.5", 0.0) → 3.5
脏串 _int_or("12abc", -1) → -1 _float_or("999.06Kb", -1.0) → -1.0
空串 _int_or("", -1) → -1 _float_or("", -1.0) → -1.0
容器 / struct _int_or([1,2], 0) → 0 _float_or([1,2], 0.0) → 0.0
非字符串（int/float/bool/null） 与 _int 同口径 与 _float 同口径

为什么要有它：_float("999.06Kb") 是抛异常而不是返回 0 —— 而服务端 JSON 里 "看着像数字"的字段什么写法都有（43.64Mb / 999.06Kb / zpMb）。实测事故见 archive/移植音乐下载器实录与待办.md 的 A5「青衣」：一个畸形字段就把整次搜索炸掉， 界面只剩"没搜到结果"，排查从"看一行日志"变成"猜"。

⚠ _int / _float 的旧语义没有变（脏串仍抛异常）—— 那条被大量既有代码依赖， 改成宽容等于静默改掉别人写好的错误处理。三条路各有用途： - "这里必须是数字，坏了就该报" ⇒ _int / _float - "脏值就走兜底" ⇒ _int_or / _float_or - "想要 null 而不是默认值" ⇒ x as int / x as float（安全转换，失败给 null）

⚠⚠ as 不做"字符串 → 数值"的解析（2026-10-09 实测；as 与 is 共用 type_spec_match）： as 是类型规格匹配，不是解析器 ⇒ 任何字符串 as 数值都得到 null（连 "0" / "77" 也是）：

var s = "77"
print(s as int)       // null（不是 77 ✗）
print("3.5" as float) // null ✗

能转的是"已有表示的重新解释 + 语言已定义的规则"：1 as string → "1" ✓、 1.9 as int → 1（截断）✓、true as int → 1 ✓； 不能转的是"需要新规则（解析或判定）的"：1 as bool → null（0 算不算 false 从未定义）、 "77" as int → null（要语法分析）✗ ⇒ ""77" 不能 as int`" 不是 bug，是cast 与 parse 的职责分界 （与 Python int(x) 是函数、Rust str::parse 是方法同一道理——都不是 cast 语法）。 ⚠ 但它当前放行得比较宽松：左操作数静态类型就是 string 时编译器本可当场报 「as 不做字符串解析」，却让它编译通过、运行时静默 null ⇒ 白丢一次诊断 （待改进：在语义检查里加一条"类型对是否存在转换规则"，把恒失败的组合挡在编译期）。

⚠ _int_or 的两个实测边界（2026-10-09 初测；2026-11-16 复核并更正两行）：

输入 _int_or(s, -1) _int(s)
"99999999999999999999"（超 int64） -1 失败 ✗ 精确值 ✓（任意精度）
null -1（走默认值） 0
"abc" / "12.9" / " 42 " / "0x1F" -1 ✓ 抛异常
"-5" / "+7" -5 / 7（认符号） 同
"" / " " -1 ✓ 抛异常（2026-11-15 起；此前静默给 0 ✗）

⇒ _int_or 走的是 int64 快路径，与"int 是任意精度"这个前提不一致 ⚠ 需要任意精度 / 需要严格非负 / 需要把 null 当 0 时：先自己判形状（digits_only 之类） 再 _int ⇒ 不抛、不溢出、语义完全可控 ✓（LenoMusic 的 parsing.leno 就是这么做的）。 null 这一行是两个函数口径不同的已知点：_int(null) = 0，而 _int_or(null, d) = d （_int_or 把 null 当"类型不对"）—— assert/test_types_module.leno 已把两条都钉住。

将值转换为 bool 类型。

转换规则:

原始类型 值 结果 规则
null null false 空值转 false
bool true true 直接返回

int 0 false 0 转 false

_str(value) - 转换为字符串

将值转换为 string 类型。

支持的转换:

原始类型 示例 结果
null _str(null) "null"
bool _str(true) "true"
bool _str(false) "false"
int _str(123) "123"
float _str(3.14159) "3.14159"
string _str("hello") "hello"（直接返回）
大整数 _str(超大整数值) 转换为字符串（对外显示为 int） 
print(_str(123))        // "123"
print(_str(3.14159))    // "3.14159"
print(_str(true))       // "true"
print(_str(null))       // "null"

注意：容器 / struct / 异常对象都会展开成正经文本（与 print / $"{x}" / 字符串拼接 同一口径，走 value_to_string）：

var arr = [1, 2, 3]
print(_str(arr))        // "[1, 2, 3]"   ⚠ 2026-10-07 前这里是 "<object>"（B4，已修）

struct P { int x = 1 }
print(_str(new P()))    // "P{x=1}"
print("v=" + new P())   // "v=P{x=1}"

try { var _z = 1 / 0 } catch e { print(_str(e)) }   // 异常对象 ⇒ 只给 msg 文本（不是 "<object>"）

⚠ 自引用容器（d["self"] = d）会让展开无限递归 ⇒ 命中环时抛错 （转字符串失败：检测到循环引用…）并给占位 "..."（2026-11-16 修；此前栈溢出崩溃）。

_int64(value) - 截断为 64 位有符号整数

将值截断为 64 位有符号整数（环绕语义），用于 64 位运算场景。

支持的转换:

原始类型 示例 结果
int _int64(42) 42（直接返回）
float _int64(3.14) 3（截断小数）
bool _int64(true) 1
null _int64(null) 0
大整数 _int64(超大值) 截断低 64 位，解释为有符号 
_int64(42)                          // 42
_int64(0x123456789ABCDEF0)          // 1311768467463790320
_int64(0x1FFFFFFFFFFFFFFFF)         // -1（低 64 位全 1）

_uint64(value) - 转为 64 位无符号整数

将值转为 64 位无符号整数（0 ~ 18446744073709551615），用于 FFI 交互和 64 位无符号位运算。

支持的转换:

原始类型 示例 结果
int _uint64(42) 42
int（负数） _uint64(-1) 18446744073709551615
float _uint64(3.14) 3
bool _uint64(true) 1
null _uint64(null) 0
大整数 _uint64(超大值) 截断低 64 位，解释为无符号 
_uint64(42)                         // 42
_uint64(-1)                         // 18446744073709551615（= 0xFFFFFFFFFFFFFFFF）
_uint64(0x8000000000000000)         // 9223372036854775808（超过 INT64_MAX，自动转为 BigInt）

💡 超过 INT64_MAX 的值会自动转为 BigInt，确保无符号语义正确。

_uint8(value) - 截断为 8 位无符号整数

将值截断为 8 位无符号整数（0 ~ 255），用于字节操作、协议解析、颜色值等场景。

支持的转换:

原始类型 示例 结果
int _uint8(42) 42
int（超出范围） _uint8(257) 1（257 & 0xFF）
int（负数） _uint8(-1) 255
float _uint8(3.14) 3
bool _uint8(true) 1
null _uint8(null) 0 
_uint8(0xFF)            // 255
_uint8(257)             // 1（取低 8 位）
_uint8(-1)              // 255

// 提取字节
int value = 0x12345678
var b0 = _uint8(value)           // 0x78
var b1 = _uint8(value >> 8)      // 0x56

_byte(value) - _uint8 的别名

_byte 与 _uint8 完全等价，但在字节操作场景下语义更清晰。

_byte(0xFF)             // 255
_byte(257)              // 1

// 典型用法：字节提取（比 _uint8 语义更明确）
int value = 0x12345678
var b0 = _byte(value)           // 0x78（最低字节）
var b1 = _byte(value >> 8)      // 0x56
var b2 = _byte(value >> 16)     // 0x34
var b3 = _byte(value >> 24)     // 0x12

固定位宽函数对比

函数 返回范围 用途
_int32(x) -2147483648 ~ 2147483647 32 位有符号环绕
_uint32(x) 0 ~ 4294967295 32 位无符号位运算
_int64(x) -9223372036854775808 ~ 9223372036854775807 64 位有符号运算
_uint64(x) 0 ~ 18446744073709551615 64 位无符号位运算、FFI
_uint8(x) 0 ~ 255 字节操作
_byte(x) 0 ~ 255 _uint8 别名

💡 与 _int() 的区别：_int() 是类型转换，不改变数值；固定位宽函数是位宽截断，会环绕。

类型推断详解

数组类型推断

type() 会深入分析数组元素类型：

// 同类型元素
print(type([1, 2, 3]))              // "Array[int]"
print(type(["a", "b", "c"]))        // "Array[string]"

// 混合类型（类型提升）
print(type([1, 2.0]))               // "Array[float]"（int 提升为 float）
print(type([1, "hello"]))           // "Array[any]"（无法提升，变为 any）

// 嵌套数组
print(type([[1, 2], [3, 4]]))       // "Array[Array[int]]"

// 空数组
print(type([]))                     // "Array"

字典类型推断

// 同类型值
print(type({"a": 1, "b": 2}))       // "Dict[string, int]"
print(type({"x": 1.0, "y": 2.0}))   // "Dict[string, float]"

// 混合类型值
print(type({"a": 1, "b": "hello"})) // "Dict[string, any]"

// 嵌套字典
print(type({"data": {"value": 100}}))   // "Dict[string, Dict[string, int]]"

// 空字典
print(type({}))                     // "Dict"

与类型守卫配合使用

类型转换函数经常与 is 类型守卫配合使用：

场景 1：安全的类型转换

func process(var x) {
    if x is int {
        // 类型守卫收窄后，可以直接使用
        int n = x
        print("整数: " + n)
    } else if x is string {
        // 尝试将字符串转换为整数
        try {
            int n = _int(x)
            print("从字符串转换: " + n)
        } catch {
            print("无法转换为整数")
        }
    } else {
        // 其他类型，先转字符串再处理
        string s = _str(x)
        print("其他类型: " + s)
    }
}

process(42)         // 整数: 42
process("100")      // 从字符串转换: 100
process("abc")      // 无法转换为整数
process([1, 2])     // 其他类型: [1, 2]     （容器会展开，不是 "<object>"）

场景 2：处理 any 参数

// 不推荐：直接使用 any
func bad_add(var a, var b) {
    return a + b    // 编译通过，但可能运行时错误
}

// 推荐：先检查再转换
func safe_add(var a, var b) {
    if a is int and b is int {
        return a + b                    // ✅ 直接使用（已收窄）
    }

    // 尝试转换为数字
    var num_a = a
    var num_b = b

    if a is string {
        num_a = _int(a)                 // 转换字符串为 int
    }
    if b is string {
        num_b = _int(b)                 // 转换字符串为 int
    }

    return num_a + num_b
}

print(safe_add(1, 2))           // 3
print(safe_add("10", "20"))     // 30

场景 4：用户输入处理

func get_user_input(string prompt):int {
    while true {
        print(prompt)
        var input = input()         // 获取用户输入（字符串）

        if input == "quit" {
            return 0
        }

        try {
            return _int(input)      // 尝试转换为整数
        } catch {
            print("无效输入，请输入数字！")
        }
    }
    return 0
}

var age = get_user_input("请输入年龄: ")
print("您的年龄是: " + age)

注意事项

  1. 转换失败会报错：所有 _xxx() 函数在转换失败时会抛出运行时错误，建议使用类型守卫先做检查。
  1. 与类型守卫的关系：
    • is 类型守卫用于编译时类型收窄（更安全）
    • _xxx() 转换函数用于运行时类型转换（更灵活）
  1. 优先使用类型守卫：
// 推荐：使用类型守卫（编译时检查）
func good(var x) {
    if x is int {
        return x * 2        // ✅ 安全，编译器知道 x 是 int
    }
    return 0
}

// 不推荐：直接转换（可能运行时错误）
func bad(var x) {
    return _int(x) * 2      // ❌ 可能运行时错误
}
