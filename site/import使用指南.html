Leno Import 使用指南

快速入门

基本语法

// 导入模块并使用默认名称（文件名）
import "math.leno"
math.add(1, 2)  // 使用模块名访问

// 导入并指定别名
import "string_utils.leno" as str
str.trim("  hello  ")  // 使用别名访问

// 从子目录导入
import "utils/array_helper.leno" as arr

// 使用 use 导入类型（支持 struct、clib、face、enum、alias）
import "point.leno" as pt
use pt.Point      // 将 Point 类型导入当前作用域
Point p = new pt.Point()  // 现在可以直接使用 Point 类型

// 批量 use 导入：从同一模块导入多个类型
import "shape.leno" as shape
use shape.(Point, Circle, Rect)   // 等价于三行单独的 use 语句

0. 三条硬约束（先看这个）

这三条不是风格偏好，是会当场编译失败或静默出错的硬规则 ⚠

0.1 import 必须写在任何使用它的语句之前（含 const 定义）

模块级初始化按文本顺序进行：模块别名在 import 那一行才被绑定。 把 import 放到文件头的常量定义之后，就会报两个误导性错误：

import "./songrow.leno" as srow

export const int F_ID = srow.F_ID     // ✅ 成立

export const int F_ID = srow.F_ID     // ❌ 「未定义的变量: srow」
                                     // ❌ 「初始化值类型是 any（期望 int）」
import "./songrow.leno" as srow      // ← 放在这里就已经晚了

⇒ 约定：import / use 提到文件最前（常量、注释块都可以排在它们后面）。 这也是为什么很多模块头部是"文件头注释 → import → 常量 → 函数"的顺序。

0.2 use 必须列全本文件源码里真正用到的类型

use mod.(A, B) 是把类型引进当前作用域 ⇒ 少列一个，编译期报 「类型未解析」，而报错位置在 use 那一行，与真正缺的那个类型毫无关系。

最容易漏的是"传导型"类型：从另一个模块传进来的类型也算在本文件头上。

import "SDL3" as SDL3
use SDL3.(Event, Renderer, Button, Scancode, Window)     // 用了 Window 就必须列 Window
Window win = SDL3.createWindow(...)                       // 漏了 Window ⇒「类型未解析」✗

⚠ 这类漏列静态检查 / lint 抓不到（源码里类型名只出现在 use 里）， 必须真编译或真运行才会暴露 ⇒ 写完模块先跑一次 -c 编译验证。

★ 2026-10-12（US1）：漏列不再是死路 —— 类型位置可以直接写限定名（m.Pt）， 它等价于隐式 use m.Pt（见 §8.2 的规则表与 类型可见性与use逃生阀修复追踪.md）。 所以本节的"必须列全"更准确的表述是：一旦你写了 use，就得列全 ✓； 而"不写 use、直接用 m.Pt"现在是另一条合法出路 ✓（这条正是本节这类坑的逃生阀）。

0.3 模块级只要不加 export 就是文件私有；pri 只用于结构体成员

  • 模块级函数不能写 pri func ⇒ 报「语法错误：期望表达式」，错误信息指不到真正病因 ✗
  • 文件私有 = 不写 export（不是写 pri）：func helper() 只在本文件可见 ✓
  • 跨文件使用 ⇒ 必须 export + 在使用方 import / use
func helper(): int { return 1 }        // ✅ 文件私有
export func helper(): int { return 1 } // ✅ 对外可见
pri func helper(): int { return 1 }    // ❌ 语法错误（pri 只对 struct 成员有意义）

1. 导入方式详解

1.1 基本导入

// 同一目录下的模块
import "module.leno"

// 子目录中的模块
import "subfolder/module.leno"

// 上级目录的模块
import "../parent_module.leno"

1.2 使用别名

当模块名冲突或太长时，使用 as 指定别名：

import "folder1/utils.leno" as utils1
import "folder2/utils.leno" as utils2

main() {
    print(utils1.get_info())  // 使用别名区分
    print(utils2.get_info())
}

1.3 特殊字符路径

Leno 支持中文路径、空格路径等特殊字符：

// 中文路径
import "中文文件夹/中文模块.leno" as cn

// 空格路径（需要引号）
import "folder with spaces/space module.leno" as sp

// 横线路径
import "folder-with-dashes/dash-module.leno" as dash

1.4 内置模块名是保留名（2026-11-18 起）

io / times / arrays / strings / maths / rands / files / asyncs / dirs / jsons / sockets / ffi / threads / regexs 这 14 个名字属于内置模块。裸名导入永远指向内置模块， 不会被当前目录（或搜索路径里）的同名 .leno 抢走：

// 假设当前目录里恰好有一个 ffi.leno（比如你放了个测试文件）
import ffi          // ⇒ 内置模块 ffi（编译器会警告：那个 ffi.leno 被忽略）
import "ffi.leno"   // ⇒ 那个本地文件（带 .leno ⇒ 按文件路径解析）

为什么要立这条规矩：此前裸名 import ffi 会先在本目录命中 ffi.leno， 于是 ffi 变成那个脚本、ffi.load(...) 在运行期报「函数未定义」—— 指向 ffi.load 那一行，与真实原因（模块被同名文件替换）毫无关系， 桌面和手机上表现一致、只取决于目录里有没有那个文件，极难定位。 现在内置优先，且被忽略的文件会明确报出来（警告类别 内置模块被同名文件遮蔽）。

与 import … as 别名 的既有规则同口径：别名也不能用内置模块名。

2. 模块导出规则

2.1 显式导出

Leno 模块使用 export 关键字显式导出需要暴露的顶层定义：

// math.leno
export func add(int a, int b):int {
    return a + b
}

export var PI = 3.14159

export struct Point {
    int x = 0
    int y = 0
}

导入后可以直接使用：

import "math.leno" as math

var p = new math.Point()      // 使用导出的 struct
var sum = math.add(1, 2)      // 使用导出的函数
var pi = math.PI              // 使用导出的变量

2.2 私有成员

没有 export 关键字的标识符不会导出：

// module.leno
export var public_var = 42    // ✅ 导出
var _private_var = 100        // ❌ 不导出（无 export）

export func public_func() { } // ✅ 导出
func _helper() { }            // ❌ 不导出（无 export）

2.3 导出控制建议

// ✅ 好的做法：显式控制导出
export var public_api = "可用"
var _internal_state = 0       // 内部状态不暴露

export func public_function() {  // 对外接口
    _helper()
}

func _helper() {              // 内部辅助函数
    // ...
}

2.4 导出变量：读写都是同一份存储（实时）

// counter.leno
export var count = 0
export const LIMIT = 99

export func bump(): int { count = count + 1; return count }

import "counter.leno" as c

main() {
    c.bump()
    c.bump()
    print(c.count)      // ✅ 2   —— 模块内一改，这里立刻能看到

    c.count = 100       // ✅ 真的写进去了（写穿到模块自己的存储）
    print(c.count)      // ✅ 100
    c.count += 5        // ✅ 复合赋值同样生效
    print(c.bump())     // ✅ 106 —— 模块内部接着从 105 往上加

    c.LIMIT = 1         // ❌ 编译错误：const 变量不可修改
    c.bump = 1          // ❌ 编译错误：函数不是变量，不能赋值
}
  • 读（2026-10-24 起）：m.变量 是实时值 —— OP_SET_MODULE_VAR 写完模块全局槽后 按「槽位 → 导出名」反查表顺手刷新 exports（实现见 10_vars_module.inc）。
  • 写（2026-10-25 起）：m.变量 = 值 / m.变量 += 值 编译成 OP_INDEX_SET(值, 模块对象, "变量名")，VM 按 module->export_mappings 写穿到 module->globals[槽位] 并同步 exports ⇒ 模块内外是同一份存储（此前 m.x = v 是 "零报错零效果"：赋值指令压根没生成）。
    • ⚠ m.变量++ 不支持（++ 只用于变量或索引）；写 m.变量 += 1。
    • ⚠ 只能写 export var：const 变量、函数、类型、未导出成员都写不了（编译期拦）。
    • ⚠ 会按提供端声明的类型做检查（m.count = "hi" ⇒ 编译错误）。
  • 跨模块改容器元素一直是引用语义（c.items.add(1)、c.items[0] = 99 改的是同一个 对象 ✓）；c.items = [...] 换整个容器走上面那条写穿路径。

3. 模块使用模式

3.1 命名空间模式

使用别名创建命名空间，避免命名冲突：

import "core/math.leno" as math
import "core/string.leno" as str
import "core/array.leno" as arr

main() {
    var nums = [1, 2, 3]
    var sum = math.add(nums[0], nums[1])
    var msg = str.format("Sum: {0}", sum)
    arr.add(nums, 4)
}

3.2 选择性导入

Leno 目前不支持 ES6 式的选择性导入，但可以通过别名实现类似效果：

// 只使用需要的功能
import "math.leno" as m

func calculate(int x):int {
    return m.add(x, 10)
}

3.3 重导出（Re-export）

模块可以聚合其他模块的导出：

// core.leno - 核心模块聚合
import "math.leno" as math
import "string.leno" as str
import "array.leno" as arr

// 重导出变量
export var math_add = math.add
export var PI = math.PI

// 包装后导出
export func enhanced_add(int a, int b):int {
    print("计算中...")
    return math.add(a, b)
}

使用聚合模块：

import "core.leno" as core
core.enhanced_add(1, 2)

3.4 导出类型别名（export alias）

模块可以通过 export alias 导出类型别名，让调用方直接使用别名类型：

// types.leno
export alias Size = int
export alias IntList = Array[int]
export alias StrDict = Dict[string, string]

// main.leno
import "types.leno" as t
import types

main() {
    Size w = 100              // Size 被识别为 int
    IntList arr = [1, 2, 3]   // IntList 被识别为 Array[int]
    StrDict d = {"a": "hi"}   // StrDict 被识别为 Dict[string,string]
}

支持的复杂类型：Array[T]、Dict[K,V]、自定义 struct 名等。

use 导入 alias：use 也支持导入其他模块的 export alias：

// types.leno
export alias MySize = Dict[string,int]
export alias MyColor = Dict[string,float]

export func makeSize(int w, int h): MySize {
    return {w: w, h: h}
}

// main.leno
import "types.leno" as t
import types
use t.MySize       // 将 MySize 别名导入当前作用域

main() {
    MySize s = {w: 100, h: 200}   // ✅ 直接使用 MySize 类型名
    var sz = t.makeSize(50, 75)   // 也可以通过模块调用
}

alias 作为跨模块函数返回类型：use 导入的 alias 可以作为 export func 的返回类型：

// wrapper.leno - 中间层 use alias 并作为返回类型
import "types.leno" as t
use t.MySize

export func createSize(int w, int h): MySize {   // ✅ MySize 作为返回类型
    return t.makeSize(w, h)
}

// main.leno - 调用方正确推断返回类型
import "wrapper.leno" as w

main() {
    var s = w.createSize(100, 200)   // s 被推断为 MySize (即 Dict[string,int])
    print(s.w)                       // ✅ 可直接访问字段
}

别名链——export alias 可以引用同模块内的其他别名：

// types.leno
export alias A = int
export alias B = A          // B → A → int

// main.leno
import "types.leno" as t
B val = 42                  // B 最终解析为 int

3.5 导出 face 类型

模块可以导出 face 定义，供调用方实现或作为参数类型：

// shape.leno
export face Shape {
    func area():float
    func name():string
}

export struct Circle impl Shape {
    int r = 0
    func area():float { return 3.14 * r * r }
    func name():string { return "Circle" }
}

// main.leno
import "shape.leno" as sm
use sm.Shape

func print_info(Shape s) {
    print(s.name() + " 面积=" + s.area())
}

main() {
    var c = new sm.Circle(r = 3)
    print_info(c)
}

4. 循环依赖处理

4.1 循环依赖支持

Leno 支持模块间的循环依赖：

// module_a.leno
import "module_b.leno" as mb

var a_value = 100

func a_func():string {
    return "A calls B: " + mb.b_value
}

// module_b.leno
import "module_a.leno" as ma

var b_value = 200

func b_func():string {
    return "B calls A: " + ma.a_value
}

4.2 循环依赖注意事项

// ⚠️ 避免在模块初始化时相互调用

// module_a.leno - 危险！
import "module_b.leno" as mb
var a_value = mb.b_value  // 可能导致未定义行为

// ✅ 安全的做法：通过函数延迟访问
import "module_b.leno" as mb

var a_value = 100

func get_b_value():int {
    return mb.b_value  // 运行时调用，安全
}

4.3 循环依赖最佳实践

// ✅ 好的设计：单向依赖优先
// 如果可能，重构为单向依赖

// utils.leno - 基础工具（无依赖）
func helper() { }

// module_a.leno - 依赖 utils
import "utils.leno"

// module_b.leno - 依赖 utils 和 module_a
import "utils.leno"
import "module_a.leno"

5. 模块缓存机制

5.1 单例模式

Leno 模块是单例的，多次导入返回同一实例：

// counter.leno
var count = 0

func increment():int {
    count = count + 1
    return count
}

func get_count():int {
    return count
}

// main.leno
import "counter.leno" as c1
import "counter.leno" as c2  // 同一个模块！

main() {
    c1.increment()  // count = 1
    c1.increment()  // count = 2
    print(c2.get_count())  // 输出: 2（共享状态）
}

5.2 利用缓存实现状态共享

// config.leno - 全局配置
var settings = {
    debug: false,
    timeout: 30
}

func set_debug(bool value) {
    settings["debug"] = value
}

func get_config():Dict {
    return settings
}

// module_a.leno
import "config.leno" as cfg
cfg.set_debug(true)

// module_b.leno
import "config.leno" as cfg
// 可以看到 module_a 的修改
print(cfg.get_config()["debug"])  // true

6. 错误处理

6.1 导入错误类型

错误类型 示例 处理方式
模块不存在 import "not_exist.leno" 编译错误
语法错误 模块内有语法错误 编译错误，指出位置
运行时错误 模块初始化失败 运行时异常
循环依赖错误 初始化时循环调用 可能导致栈溢出

6.2 防御性导入

// ⚠️ import 是编译期指令，模块不存在会在编译阶段报错，
//    try-catch 无法捕获"模块文件找不到"这类编译期错误。
//    try-catch 只能捕获模块初始化时的运行时异常：

import "optional_module.leno" as opt

try {
    opt.do_something()
} catch e {
    print("模块运行时出错，使用默认行为: " + e)
    // 使用默认实现
}

6.3 模块版本检查

// version.leno
var VERSION = "1.2.3"

func check_version(string required):bool {
    // 简单的版本比较
    return VERSION == required
}

import "version.leno" as ver

main() {
    if not ver.check_version("1.2.3") {
        print("警告：版本不匹配")
    }
}

7. 高级用法

💡 编译期语义说明：import 是编译期指令，不是运行时动态加载表达式。编译器会在编译阶段完成路径解析、模块编译和缓存。路径必须是编译期可确定的字符串字面量（如 "db/mysql.leno"），不支持用变量动态构造路径（如 import path as plugin）。

⚠ 源码模块（.leno）的 import 必须写在模块顶层（2026-11-02 起编译期强制）： 写在函数体 / if 块内时，别名不会被绑定，运行期拿到的是 null （随后 m.foo() 报「下标访问: 对象不支持索引」）。此前这里是静默通过 ✗。 原生模块（ffi / maths / times 等）不绑定变量，写在函数体内仍是 合法惯用法（仓内回调里大量 import ffi），不受此限 ✓。

7.1 模块条件选择

源码模块的 import 要提到顶层（两个模块都会在编译期加载/缓存），运行期按条件 选择要用的那个引用：

// 顶层导入两个实现
import "db/mysql.leno" as mysql_db
import "db/sqlite.leno" as sqlite_db

func get_database_module(bool use_mysql) {
    if use_mysql {
        return mysql_db
    }
    return sqlite_db
}

如果写成"函数内 if 里各 import 一个"，2026-11-02 之前会编译通过但别名是 null （运行期才发现）；现在编译器会直接报「源码模块 import 只能写在模块顶层」。

7.2 插件系统实现

由于 import 路径必须是编译期字符串常量，不支持运行时变量路径。插件系统应通过预注册模式实现——所有插件在编译期导入，运行时按名称分发：

// plugin_manager.leno
// 编译期导入所有已知插件模块
import "plugins/plugin_a.leno" as pa
import "plugins/plugin_b.leno" as pb

var plugins = {
    "plugin_a": pa,
    "plugin_b": pb
}

func register_plugin(string name) {
    // 从预注册表中查找插件，而非动态 import
    if plugins.has(name) {
        // 插件已可用
        print("插件 " + name + " 已注册")
    } else {
        print("未知插件: " + name)
    }
}

func run_all_plugins() {
    for plugins to name, plugin {
        plugin.run()
    }
}

⚠️ 不支持运行时动态路径：import 的路径必须是字符串字面量（如 "plugins/plugin_a.leno"），不能用变量（如 import path as plugin）。如果需要真正的运行时动态加载，考虑用 FFI 调用 dlopen/LoadLibrary 自行管理。

7.3 模块装饰器模式

// logging_decorator.leno

    print("调用 add({0}, {1})".format(a, b))

8.2 使用 use 语句导入类型

当需要在当前作用域中使用模块的 struct 类型进行变量声明时，可以使用 use 语句：

// shape.leno
export struct Point {
    int x = 0
    int y = 0
}

export struct Circle {
    float radius = 1.0
}

// main.leno
import "shape.leno" as shape
use shape.Point      // 将 Point 类型导入当前作用域

main() {
    // ✅ 现在可以直接使用 Point 类型
    Point p = new shape.Point()
    print(p.x)

    // ❌ 没有 use Circle，不能直接用 Circle 类型声明
    // Circle c = new shape.Circle()  // 错误：Circle 未定义

    // ✅ 可通过模块路径创建实例（无需 use）
    var c = new shape.Circle()         // 普通 struct
    var b = new shape.Box[int]()       // 泛型 struct 也支持
}

use 语句规则：

用法 支持 说明
use module.Struct ✅ 导入后可用 new Struct() 或 new Struct[Type]()
use module.CStruct ✅ 导入 cstruct 类型，可用 CStruct.malloc()
use module.Clib ✅ 导入 clib 类型到当前作用域，可用 ClibName var = module.loadLib()
use module.Face ✅ 导入 face 类型到当前作用域
use module.Alias ✅ 导入类型别名到当前作用域，可直接作为类型名使用
use module.Enum ✅ 导入 enum 类型，可用 EnumName.Member 或链式 import B; use B.Enum
use module.(A, B, C) ✅ 批量导入，等价于多行单独 use，支持尾逗号
use module.func ❌ 函数必须通过模块名访问
use module.var ❌ 变量必须通过模块名访问
module.Type（在类型位置直接写，不 use） ✅ 2026-10-12（US1）起：等价于隐式 use module.Type ⇒ 声明 / 形参 / 返回 / 字段 / 泛型实参 / is / as / new 全位置可用 ✓（一个 use 都不写也能走 ✓）
module.A.B（多级限定） ❌ 类型位置最多一级：模块.类型 ✓（多级会报「不支持的模块限定类型名…最多只能写一级」）
module.func（在类型位置） ❌ 类型位置要的是类型；函数/常量请按 module.func(...) 调用 ✓

use 与"直接写 module.Type"的关系（2026-10-12 起）：

  • use 仍推荐（出处集中、名字短 ✓），但它不再是唯一出路 ⇒ 从"义务"变回"便利" ✓
  • 两者的语义完全相同：直接写 module.Type 走的就是 use 的同一份实现 （所以报错文案、可用性判据、重复导入的宽容度三条不可能漂移 ✓）
  • 好处（US1 的动机）：§0.2 那类"漏列一个、报错点在 use 那一行"的坑整类消失； 库的中间层也不必为了传类型而 use 一个自己用不到的名字 ✓
  • ⚠ 仍有两条纪律：多级限定不支持（最多 模块.类型）✓； cstruct 跨线程那条限制与本机制无关（那是跨线程克隆的事 ✓）

为什么 use 只支持 struct/cstruct/clib/face/alias/enum？

  • struct：编译时类型，需要用于变量声明（如 Point p）
  • cstruct：FFI C 结构体类型，需要用 Type.malloc() 分配内存
  • clib：FFI 库类型，需要用于变量声明（如 core_lib c = module.loadCore()）
  • face：编译时类型，需要用于函数参数（如 func printArea(Shape s)）
  • alias：类型别名，编译期展开为实际类型，需要用于变量声明或返回类型
  • enum：编译时常量类型，导入后可用 EnumName.Member 访问值
  • func/var：运行时实体，必须通过模块名访问（如 module.func()）

8.2.1 使用 use 导入 enum

// key.leno
export enum Key { ESCAPE = 41; SPACE = 44; A = 4 }

// main.leno
import "key.leno" as k
use k.Key

main() {
    if e.scancode() == Key.ESCAPE { print("退出") }
}

enum 支持链式传导——模块 B use a.Key 后，模块 C import B; use B.Key 也可访问 Key.ESCAPE。

8.3 use 类型链式传导

use 的类型可以通过模块链自动传递，无需手动重导出：

// d.leno - 最底层定义类型
export struct Vec3 {
    int x = 0
    int y = 0
    int z = 0
}

// c.leno - use d 的类型
import "d.leno" as d
use d.Vec3

// b.leno - use c 中传递的类型
import "c.leno" as c
use c.Vec3

// a.leno - use b 中传递的类型
import "b.leno" as b
use b.Vec3

// main.leno - 最终使用端
import "a.leno" as a
use a.Vec3

main() {
    Vec3 v = new a.Vec3(x = 1, y = 2, z = 3)
    print(v.x)    // 1
}

★ 传导式 use（2026-10-12 正式命名，原 US4）

上面那条链里，c.leno / b.leno 自己并不使用 Vec3 —— 它们 use 它的唯一目的是 把它传给下游 ✓。这个用法有正式名字：传导式 use（"我不用，我给下游用"）。

三条纪律： 1. 允许并推荐：它与"自用 use"共用同一行语法、同一条实现 ✓（不必绕 export） 2. 意图靠注释说清：use c.Vec3 后面写一句 // 传导：给下游用 —— 因为语法上区分不出来 ✓ （use 只有一种写法；本仓也没有"use 了没用"的诊断 ✓ 见 语言陷阱速查 ㉝ 一带） 3. ★ 但：2026-10-12（US1）起优先直接写限定名 ✓ —— 下游不必再依赖中间层传导： 谁是类型的定义者就写谁（import "d.leno" as d + d.Vec3 v = … ✓）。 ⇒ 传导链只在"想让下游少写一个 import"时才有必要 ✓

决定：不引入 export use（原 US4 的"另一半"）。理由：Rust 需要 pub use 是因为 没有"类型位置可以全限定"这条路；Leno 有了（US1）⇒ 新增关键字的收益是"少写一个 import"， 代价是多一条语法与一条"它算导出吗"的规则 ⇒ 不划算 ✗。要重新导出就写普通 use + 注释（上面第 2 条）✓

多个模块的类型可以同时 use：

import "point_mod.leno" as pm
import "color_mod.leno" as cm
use pm.Point
use cm.Color

main() {
    Point p = new pm.Point(x = 10, y = 20)
    Color c = new cm.Color(r = 255, g = 128, b = 0)
}

同一模块的多个类型可用批量 use 导入：

import "shape_mod.leno" as sm
use sm.(Point, Circle, Rect, Color)

main() {

8.4 use 类型作为 export func 返回类型

use 导入的 struct/face 类型可以直接作为 export func 的返回类型，调用方能正确推断返回值类型：

// item.leno - 底层模块定义 struct
export struct Item {
    int id = 0
    string label = ""

    func describe(): string {
        return "Item(" + id + ":" + label + ")"
    }
}

export func makeItem(int id, string label): Item {
    return new Item(id = id, label = label)
}

// wrapper.leno - 中间层通过 use 导入 Item 并作为返回类型
import "item.leno" as item
use item.Item

export func createItem(int id, string label): Item {
    return item.makeItem(id, label)
}

// main.leno - 调用方正确推断返回类型为 Item
import "wrapper.leno" as wrapper

main() {
    var it = wrapper.createItem(1, "hello")   // it 被推断为 Item，不是 any
    print(it.describe())                       // ✅ 可以直接调用 Item 的方法
}

face 类型同样支持：

// base.leno
export face Describable {
    func describe(): string
}

export struct Item impl Describable {
    int id = 0
    func describe(): string { return "Item(" + id + ")" }
}

export func makeItem(int id): Item {
    return new Item(id = id)
}

// mid.leno - use 导入 face 并作为返回类型
import "base.leno" as base
use base.Describable

export func getDescribable(): Describable {
    return base.makeItem(42)
}

// main.leno
import "mid.leno" as mid
use mid.Describable

main() {
    var d = mid.getDescribable()    // d 被推断为 Describable（face 类型）
    print(d.describe())             // ✅ 可以调用 face 定义的方法
}

8.6 clib 类型跨模块使用

use 也支持导入其他模块定义的 clib 类型：

// sdl_base.leno - 底层模块定义 clib
import ffi

export clib renderer_lib {
    i32 do_something(i32 x)
}

renderer_lib g_renderer = null

export func loadRenderer(): renderer_lib {
    if g_renderer == null {
        g_renderer = ffi.load("mylib.dll")
    }
    return g_renderer
}

// sdl_wrapper.leno - 中间层 use 底层 clib 并重新导出
import "sdl_base.leno" as base
use base.renderer_lib

export func getRenderer(): renderer_lib {
    return base.loadRenderer()
}

// main.leno - 最终使用端，只需感知中间层
import "sdl_wrapper.leno" as sdl
use sdl.renderer_lib

main() {
    // ✅ clib 类型正确推断
    renderer_lib r = sdl.getRenderer()
    var result = r.do_something(42)  // ✅ clib 返回值自动展开（i32→int），无需 as 转换
}

💡 零摩擦 FFI：clib 函数返回值会根据 C 声明类型自动展开为 Leno 原生类型（i32/u32/i64→int，f32/f64→float，str8/str16→string），无需 as 转换。详见 FFI 使用指南 §1.4。cstruct 字段（如 pt.x、e.id）同理自动转换。

💡 clib 导出的两种方式： - 直接导出：export clib renderer_lib { ... }，其他模块可直接 use base.renderer_lib - 间接导出：clib sdl3 { ... } + export func lib(): sdl3 { ... }，通过返回该 clib 类型的函数让符号表识别（SDL3 项目 sdl_core.leno 即用此方式）

clib 类型可以用于 struct 字段：

import "sdl_base.leno" as base
use base.renderer_lib

struct RendererHolder {
    renderer_lib renderer = null
    string       name     = ""
}

main() {
    var h = new RendererHolder(renderer = base.loadRenderer(), name = "main")
    renderer_lib r = h.renderer              // ✅ 跨模块后类型正确推断
    var v = r.do_something(10)               // ✅ 返回值自动展开，无需 as
}

💡 struct 字段 clib 类型跨模块：使用 use 导入包含 clib 字段的 struct 后，字段类型会自动保留为 clib 类型，不再需要中间变量绕开。

8.7 cstruct 跨模块使用

use 也支持导入其他模块定义的 cstruct 类型。cstruct 是 FFI 中用于映射 C 结构体的类型定义，可以通过 use 导入后直接使用：

方式一：use 导入后直接使用类型名

// cs_def.leno - 底层模块定义 cstruct
import ffi

export cstruct TT {
    u32 id
    u32 value
}

export func makeTT(u32 id, u32 value): TT {
    var t = TT.malloc()
    t.id = id
    t.value = value
    return t
}

// main.leno - use 导入 cstruct 类型
import "cs_def.leno" as cs
use cs.TT

main() {
    // ✅ 直接使用 TT 类型名创建实例
    var t = TT.malloc()
    t.id = 1
    t.value = 100
    print("id=" + t.id + " value=" + t.value)
    t.free()

    // ✅ 也可以调用模块导出的工厂函数
    var t2 = cs.makeTT(3, 300)
    print("makeTT: id=" + t2.id + " value=" + t2.value)
    t2.free()
}

方式二：通过模块路径直接访问

如果不使用 use，也可以通过模块路径直接访问 cstruct：

// main.leno - 不用 use，通过模块路径访问
import "cs_def.leno" as cs

main() {
    // ✅ 通过模块路径创建实例
    var t = cs.TT.malloc()
    t.id = 1
    t.value = 100
    print("id=" + t.id + " value=" + t.value)
    t.free()
}

cstruct 跨模块作为返回类型

与 struct/face 一样，cstruct 也可以作为 export func 的返回类型，调用方能正确推断：

// wrapper.leno - 中间层 use cstruct 并作为返回类型
import "cs_def.leno" as cs
use cs.TT

export func createTT(u32 id, u32 value): TT {
    return cs.makeTT(id, value)
}

// main.leno - 调用方正确推断返回类型
import "wrapper.leno" as w

main() {
    var t = w.createTT(5, 500)   // t 被推断为 TT 类型
    print("id=" + t.id + " value=" + t.value)  // ✅ 可以直接访问字段
    t.free()
}

⚠️ 注意：cstruct 字段值是 C 类型（u32、i32、f64 等），参与 Leno 运算时会自动转换为 int/float。

11. 常见问题

Q: 如何查看模块导出了什么？

A: 目前 Leno 没有内省功能，建议查看模块源码或文档。

Q: 模块可以热重载吗？

A: 目前不支持，模块在程序启动时加载并缓存。

Q: 如何处理模块版本冲突？

A: 使用不同别名导入不同版本：

import "lib/v1/api.leno" as api_v1
import "lib/v2/api.leno" as api_v2

Q: 相对路径的基准是什么？

A: 相对于当前文件所在的目录。
