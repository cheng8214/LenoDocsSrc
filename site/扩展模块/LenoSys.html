📦 扩展模块（非语言内置标准库）· 包名 LenoSys · import 名 "Sys" 源：Leno/build/leno_module/LenoSys/lib/Sys.leno（本页是手写文档，不从 README 同步）

LenoSys v0.2.0

跨平台的系统信息与桌面集成：进程、磁盘卷、回收站、通知、开机自启、已装软件。 Windows 走 Win32 API，Linux 走 /proc + 标准命令，同一套 API 两个平台都能跑。

import "Sys" as Sys
use Sys.(VolumeInfo, SysInfo)

SysInfo i = Sys.sysInfo()                       // OS / CPU / 内存 / 运行时长 / 是否管理员
for Sys.listVolumes() to v {                    // 每个盘/挂载点：卷标、文件系统、类型、容量
    print(v.root + "  " + v.label + "  " + v.fsType + "  剩余 " + _str(v.freeBytes))
}

与 module_sys.md 的分工：那一页讲内置全局函数（_os() / _env() / _exec() / _args()…， 不需要 import）；本页讲扩展模块 import "Sys" as Sys 提供的东西。两者不重叠。

磁盘与卷（v0.2 起含 listVolumes）

函数 返回 说明
listDrives() Array[string] 只要路径（C:\ / /）；保留兼容
listVolumes() Array[VolumeInfo] 卷标 + 文件系统 + 类型 + 容量，一次取齐
diskSpace(path) Dict{ok,total,free} 该路径所在卷的字节数
diskUsagePercent(path) int 0..100；取不到 ⇒ -1
volumeOf(path) string 该路径属于哪个卷/挂载点（判不出 ⇒ ""，不猜）

VolumeInfo 字段：

struct VolumeInfo {
    string root = ""        // "C:\\" 或 "/" 或 "/media/u/U盘"
    string label = ""       // 卷标；Linux 给设备名（/dev/sda1 —— 没有统一卷标概念）
    string fsType = ""      // NTFS / FAT32 / exfat / ext4 …
    int serial = 0          // Windows 卷序列号；Linux 恒 0
    int driveType = 0       // Windows GetDriveTypeW 原值；Linux 恒 0
    string kind = ""        // removable / fixed / network / cdrom / ram / unknown
    int totalBytes = 0
    int freeBytes = 0
    bool ready = false      // 能否取到容量
}

契约（踩过才知道）：

  • ready=false 时 totalBytes/freeBytes 一定是 0，但它的含义是「未就绪」而不是「空盘」： 空的光驱、已拔出的 U 盘、无权限的网络盘都会这样。上层应显示"未就绪"，别画成 0/0 的进度条。
  • 取不到就留空，绝不编：卷标取不到给 ""，不是 "本地磁盘" 之类猜出来的名字。
  • listVolumes 每次调用都会真查容量（Windows: GetDiskFreeSpaceExW；Linux: 每个挂载点一次 df -B1 子进程） ⇒ 别每帧调，缓存到自己的状态里按需刷新。
  • Linux 侧过滤虚拟文件系统（proc / sysfs / tmpfs / cgroup* / squashfs …）， 否则容器里能列出几十个无意义条目、白跑几十次 df。kind 按挂载点前缀推断 （/media/、/mnt/、/run/media/ ⇒ removable，其余 fixed）。
  • ⚠ Linux 分支未在真实机器上实测（开发机只有 Windows）：/proc/mounts + df 的格式解析有单测 （parse_mounts_detail / parse_df），但整条链路的实际输出请以你在 Linux 上跑 test_sys_volumes 为准。
  • macOS 目前复用 Linux 分支（没有 /proc）⇒ sysInfo() 的多数字段会是空/0； volumeOf / diskSpace 走 df 仍可用（GNU/BSD 两版的 df 输出解析器都吃）。

实时资源（v0.2 起）

函数 返回 说明
memoryUsage() MemUsage{totalKb, availKb, usedKb, percent} 当前内存用量
cpuUsage() int CPU 使用率 0..100；首次调用返回 -1 
MemUsage m = Sys.memoryUsage()
int cpu = Sys.cpuUsage()          // 第一次 -1（无基准），之后才有意义
// GUI 里每 0.5~1 秒调一次，别每帧

契约：

  • memoryUsage() 取不到时返回全 0，判 totalKb == 0 就是"未知"——别当成 100% 占满， 否则告警页在没权限的机器上会一直报警。
  • cpuUsage() 第一次返回 -1（没有基准算不出差值），之后用"距上次采样的差值"算； 采样间隔不足（同一毫秒内连调）时返回上一次的结果，不会在数字与 -1 之间反复横跳。 建议 0.5~1 秒一次：间隔太短时时间片噪声会被放大（和 top 的刷新频率是同一个取舍）。
  • 两个平台的累计值单位不同（Windows 毫秒 / Linux jiffies）⇒ 只做同平台内的差， 不要拿绝对值跨平台比较。
  • Windows 侧注意过两个坑（已在实现里处理）：GetSystemTimes 的 kernel 时间包含 idle； 累计的 FILETIME 是 100 ns 单位，开机 162 天就会超过 int48 ⇒ 内部降到毫秒再存。
  • Linux 侧：total 不含 guest/guest_nice（它们已计入 user/nice，重复计会让使用率偏低）， idle 含 iowait；该分支未在真机实测。

口径与边界

  • 绝不静默返回假数据：取不到就是 "" / 0 / false，并在注释里写清为什么取不到。
  • 不过 shell 做能直连的事：Windows 侧走 Win32 API（注册表 / Shell），只有必须的场合才起子进程； Linux 侧则大量依赖 /proc 与标准命令（df、id、ps），这是两个平台的现实差异。
  • ⚠ 模块同名冲突：import Win32 走全局搜索路径、先到先得 —— 曾因别的模块下放着陈旧 Win32.leno 副本而被顶掉（表现为"行为像旧版"）。遇到怪事跑 Sys.selfTest() 先确认拿到的是新实现。
  • ProcInfo / StartupItem / SoftwareItem / TrashItem / SysInfo / VolumeInfo 都是脚本结构体， 跨模块使用时按惯例 use Sys.VolumeInfo（或用 var v = ... 让编译器推断）。
